# KWEST DESIGN SYSTEM

> This document defines the visual language of KWEST.
>
> Every interface decision should follow these standards.
> Consistency builds trust.

---

# 1. Design Philosophy

KWEST is calm.

KWEST is trustworthy.

KWEST is familiar.

KWEST never overwhelms the user.

Every screen should help residents make better decisions with less effort.

---

# 2. Design Principles

## Community Before Commerce

Businesses are important.

Residents come first.

---

## Trust Through Consistency

Buttons, cards, badges and typography should behave consistently across the platform.

---

## Simplicity Wins

If two solutions exist,

choose the simpler one.

---

## Mobile First

Design for the phone first.

Desktop enhances the experience.

---

## Authenticity

Real places.

Real people.

Real businesses.

Real photography.

No AI-generated imagery in production whenever authentic photography is available.

---

# 5. Buttons

KWEST has only three button styles.

## Primary

Purpose

Main action.

Examples

- Browse Directory
- Join the Directory
- Read Story

Style

- Emerald background
- White text
- Rounded-xl

---

## Secondary

Purpose

Alternative action.

Examples

- Learn More
- View Business

Style

- White background
- Slate border
- Slate text

---

## Ghost

Purpose

Low emphasis.

Examples

- Cancel
- Close

Style

Transparent.

Text only.

---

# 6. Cards

Cards should have:

- Rounded corners
- Light border
- Soft shadow
- Generous spacing

Cards should never feel cramped.

---

# 7. Verified Badge

The KWEST Verified Badge represents trust.

Design

- KWEST icon
- VERIFIED label
- Emerald background
- Rounded pill
- White text

The badge should appear only after verification.

It must never be used decoratively.

---

# 8. Photography

Preferred order

1. Real photography

2. Placeholder during development

Stock photography should be avoided whenever authentic local photography exists.

---

# 9. Icons

Icons support content.

Icons do not replace content.

Icons should be consistent throughout the platform.

---

# 10. Motion

Motion should communicate.

Never distract.

Animations should be:

- Fast
- Subtle
- Purposeful

Hover effects should feel natural.

---

# 11. Spacing

Whitespace improves readability.

Never add elements simply because space exists.

Every section should breathe.

---

# 12. Accessibility

Every interactive element must be accessible.

Requirements

- Proper contrast
- Keyboard navigation
- Focus states
- Alt text
- Semantic HTML

Accessibility is part of quality.

---

# 13. Copywriting

Write for residents.

Use simple language.

Avoid corporate jargon.

Every sentence should answer a question or help someone make a decision.

---

# 14. Trust Indicators

KWEST communicates trust through:

- Verified badge
- Accurate information
- Review dates
- Real photography
- Transparent updates
- Clear contact information

---

# 15. Components

Reusable components include:

- Header
- Footer
- Hero
- Category Card
- Business Card
- Story Card
- Community Update Card
- Buttons
- Verified Badge
- Search Bar

Components should never be duplicated unnecessarily.

---

# 16. Before Shipping

Before any feature is released ask:

✓ Does this reduce noise?

✓ Does this help someone decide faster?

✓ Is it mobile friendly?

✓ Is it visually consistent?

✓ Is it trustworthy?

✓ Would we proudly show it to a Kahawa West resident?

If any answer is "No",
the feature is not ready.

---

# Design Motto

Beautiful enough to inspire.

Simple enough to use.

Trusted enough to rely on.
